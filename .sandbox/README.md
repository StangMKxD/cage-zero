# Sandbox Workspace (.sandbox)

โฟลเดอร์สำหรับพื้นที่ทดลอง (Sandbox / Staging) และการแยกทดสอบระบบ (Isolation) ก่อนนำโค้ดหรือการเปลี่ยนแปลงเข้าสู่ระบบหลัก (`src/`)

## โครงสร้างโฟลเดอร์ (Directory Structure)

- **`experiment/`**:
  - **วัตถุประสงค์**: ใช้สำหรับโค้ดทดลอง, Prototype, หรือการทดสอบฟีเจอร์ใหม่ที่อยู่ระหว่างการพัฒนา
  - **วิธีใช้งาน**: พัฒนาและทดสอบการทำงานแยกจาก `src/` เมื่อยังไม่ผ่านการอนุมัติหรือยังไม่เสร็จสมบูรณ์
- **`approved/`**:
  - **วัตถุประสงค์**: เก็บงานหรือฟีเจอร์ทดลองที่ผ่านการทดสอบ (Verification & QA) และได้รับการอนุมัติ (Approval) เรียบร้อยแล้ว
  - **วิธีใช้งาน**: เตรียมพร้อมสำหรับรวมเข้าสู่ `src/` หรือ release pipeline ตามข้อตกลงและแผนงาน
- **`rejected/`**:
  - **วัตถุประสงค์**: เก็บงานทดลองที่ไม่ผ่านเกณฑ์การทดสอบ ไม่ผ่าน Review หรือถูกยกเลิก
  - **วิธีใช้งาน**: เก็บไว้เป็นประวัติเพื่ออ้างอิง (Post-mortem / Reference) ป้องกันการทำซ้ำข้อผิดพลาดเดิม โดยไม่นำไปใช้งานจริง

## กฎและข้อพึงระวัง (Operating Guidelines)

1. การเปลี่ยนแปลงใน `.sandbox` ต้องไม่กระทบโค้ดหลักใน `src/` โดยตรงจนกว่าจะผ่านการตรวจรับ
2. รักษาข้อมูลและประวัติการทดลองเดิม ไม่ลบงานของผู้อื่น
3. ปฏิบัติตามคำสั่งและข้อกำหนดที่ระบุใน [AGENTS.md](../AGENTS.md) เสมอ
