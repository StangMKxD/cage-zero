# Agent Workspace (.agents)

โฟลเดอร์สำหรับระบบงาน Agent, บันทึกการทำงานร่วมกันของทีมงาน (Teamwork Logs), และชุดโครงร่างอ้างอิงของระบบ Agent Orchestration

## โครงสร้างโฟลเดอร์ (Directory Structure)

- **`teamwork/`**:
  - **วัตถุประสงค์**: พื้นที่จัดเก็บประวัติและสถานะการทำงานของ Worker / Agent ในแต่ละรอบงาน (เช่น `worker_m4`, `worker_m5`, `worker_m5_remediation` ฯลฯ)
  - **เนื้อหาภายใน**: เอกสารประสานงานของแต่ละ Worker เช่น `BRIEFING.md`, `DISPATCH.md`, `handoff.md`, `progress.md` รวมถึงสคริปต์เครื่องมือเฉพาะกิจ
  - **วิธีใช้งาน**: บันทึกการส่งมอบงานและการทำงานร่วมกันระหว่าง Agent ตามที่ได้รับมอบหมาย (โฟลเดอร์นี้ถูก ignore ใน `.gitignore` เพื่อไม่ให้รบกวน repository หลัก)
  - **ข้อพึงระวัง**: ต้องรักษาประวัติการทำงานเดิม (`Existing teamwork/ history is preserved`) ไม่แก้ไขหรือลบงานของผู้อื่น

- **`_system/`**:
  - **วัตถุประสงค์**: ชุดโครงร่างและเทมเพลตอ้างอิง (Reference Templates) สำหรับระบบการจัดการ Agent (คัดลอกมาจาก Project Last Wave)
  - **โครงสร้างภายใน**:
    - `roles/`: คำนิยามบทบาทและความรับผิดชอบของ Agent (Responsibility Matrix)
    - `workflows/`: แผนผังและขั้นตอนการส่งต่องาน (Delegation / Quickstart)
    - `config/`: ตัวอย่างค่าคอนฟิก เช่น บทบาท, Quality Gates, งบประมาณ Token
    - `contracts/` & `quality/`: สัญญาการส่งมอบงานและข้อกำหนดเกณฑ์คุณภาพ
    - `templates/`: แบบฟอร์มสำหรับ Task, Plan, Notes, Manifest
    - `tests/`: ตัวอย่างการทดสอบระบบ workflow
  - **สถานะและข้อเท็จจริง**: `_system/` เป็นเพียง **ชุดเทมเพลตอ้างอิง (Reference Template)** ไม่ใช่คำสั่งที่บังคับใช้โดยตรง และไม่ใช่แหล่งข้อมูลข้อเท็จจริงของโปรเจกต์ Cage Zero ข้อมูลภายในมีเส้นทาง ล็อกสโคป และการตัดสินใจของ Last Wave ซึ่งไม่สามารถนำมาใช้กับ Cage Zero ได้โดยตรง
  - **วิธีใช้งาน**: ให้ปรึกษา [AGENTS.md](../AGENTS.md), `docs/READ.md`, คำสั่งของผู้ใช้ในรอบปัจจุบัน และกฎ runtime ของโปรเจกต์นี้เป็นหลัก ต้องปรับแต่งและตรวจสอบเทมเพลตก่อนนำมาใช้งานจริงเสมอ อย่าสรุปว่าระบบอัตโนมัติทำงานเข้ากับ Cage Zero ได้ทันที

## แนวทางการใช้งาน (Usage Guidelines)

1. ยึดถือ [AGENTS.md](../AGENTS.md) และเอกสารใน `docs/` เป็นข้อตกลงหลักในการปฏิบัติงาน
2. ไม่อนุญาตให้ย้อนงาน ย้าย หรือลบประวัติใน `teamwork/` หรือข้อมูลของผู้อื่น
3. ตรวจสอบสิทธิ์และขอบเขตงานทุกครั้งก่อนเริ่มดำเนินการ
