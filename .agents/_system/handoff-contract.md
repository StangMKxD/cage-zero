# Agent Handoff Contract Specification

## 1. Purpose
This specification enforces a zero-information-loss handoff protocol between AI specialists, team leads, independent reviewers, and the orchestrator.

Reference: [docs/workflows/roblox-agent-workflow.md](../../docs/workflows/roblox-agent-workflow.md)

---

## 2. Mandatory Handoff Structure

Every handoff artifact generated by a specialist or reviewer (e.g. `engineering/handoff.md`, `animation/handoff.md`) MUST include the following eight sections:

```markdown
# Handoff: [Discipline / Task Name]

## 1. Executive Summary
- Agent Role: [e.g. Gameplay Engineer]
- Status: [PASS | REJECTED | BLOCKED | READY_FOR_REVIEW]
- Target Run: [e.g. .agents/<task-slug>/run_01]

## 2. Modified and Created Files
| File Path (Relative to Repo) | Change Type (Created/Modified) | Description |
|---|---|---|
| .sandbox/experiments/... | Created | ... |

## 3. Asset Inventory
- New Assets Created: [List or NO_EXTERNAL_ASSETS]
- Asset Types: [Animation | VFX | Rig | Audio | None]
- Asset Manifest Reference: [Relative path to assets-manifest.json if applicable]

## 4. Behavioral Contract & State Specification
- Expected Inputs: [e.g. M1 Click within combo buffer window]
- State Transitions: [Idle -> Attack1 -> Recovery -> Idle]
- Fail-Safe / Interrupt Behavior: [Stun cancels action and clears active hitbox]

## 5. Verification Steps
1. [Exact command or manual test sequence]
2. ...

## 6. Actual Test Results
- Harness Executed: [Pure Luau / Studio Harness / Not Tested]
- Environment Tag: [STUDIO_NOT_TESTED | VERIFIED_PURE_LUAU | VERIFIED_STUDIO]
- Observed Output: [Paste actual terminal output or log snippet]

## 7. Known Limitations & Technical Debt
- Constraints: [e.g. Headless test environment cannot evaluate screen-space particle blend]
- Blockers: [None or explicit list]

## 8. Verifiable Evidence Paths
- Evidence Logs: [Relative path to evidence/pilot-test-output.md or similar]
- Summary Metrics: [Relative path to exports/*.json]
```

---

## 3. Reviewer Rejection & Defect Loop
When an Independent Reviewer or QA Tester rejects a handoff:
1. Reviewer documents explicit, reproducible defects in `review/independent-review.md`.
2. Team Lead marks handoff as `REVISION_REQUIRED` and dispatches feedback to the original implementer.
3. Implementer resolves the findings, appends a revision log to the handoff, and resubmits to the Team Lead.
4. Reviewer conducts re-review. Under no circumstances may an implementer approve their own work.
