### RF-F05: Per-Copy Ownership & Durable Economic Invariants
- **เอกสารที่แก้ไข:** `docs/design/data-schema.md`, `docs/plan/phase-01-gameplay-demo/release-first/RF-02/{plan,tasks}.md`, `RF-05/{plan,tasks,notes}.md`, `RF-07/{plan,tasks,notes}.md`, และ `release-first/plan.md`
- **การเปลี่ยนแปลง:**
  1. ปรับ Profile Schema จาก `ownedCharacters: { string }` เป็น **Per-Copy Ownership** โดยนิยาม `CharacterInstance`:
     ```luau
     export type CharacterInstance = {
         instanceId: string,       -- รหัสเฉพาะประจำสำเนาตัวละคร (UUID/Timestamp)
         characterId: string,      -- รหัสอ้างอิงต้นแบบตัวละคร (เช่น "char_speedster_01")
         acquiredAt: number,       -- เวลา Unix timestamp ที่ได้รับตัวละคร
         level: number,            -- เลเวลพัฒนาการของตัวละครสำเนานี้
     }
     ```
     และปรับ `ownedCharacters: { CharacterInstance }` เพื่อเก็บรักษาทุกสำเนาที่ผู้เล่นสุ่มได้ ไม่มีการสูญหายของข้อมูล
  2. ระบุสถานะ Duplicate Outcome Policy เป็น **PENDING Owner Decision** (ถอนข้อความ commit เรื่อง Duplicate Conversion ออกทั้งหมด เนื่องจาก Owner ยังไม่ได้เลือกนโยบายแปลงตัวซ้ำ)
  3. กำหนด **4 Durable Economic Invariants** ในเอกสารสเปกและ Tasks:
     - *Atomic Debit + Grant:* การหักเงิน การมอบสำเนาตัวละคร และการบันทึก Request Result ต้องเกิดขึ้นใน Logical Transaction เดียวกัน
     - *Uncertain Outcomes Reconciled:* ข้อผิดพลาดที่ไม่แน่นอนระหว่างบันทึก DataStore ต้อง Reconcile คืนสถานะถูกต้องเมื่อ Reconnect
     - *Retry Not Rerolled:* การ Retry คำขอเดิมจาก Client ต้องไม่ทำให้เกิดการสุ่มเรตใหม่ แต่ต้องคืนผลลัพธ์เดิมที่เคยตัดสินแล้ว
     - *Request Deduplication:* การใช้ Request ID เดิมซ้ำต้องไม่ทำให้เกิดการหักเงินหรือให้สิทธิ์ตัวละครซ้ำสอง (Strict Idempotency)
  4. ใน RF-07 ปรับให้การทดสอบ `ProcessReceipt` สำหรับสินค้า Robux เป็นเงื่อนไข **Conditional on selecting a launch product** โดยหาก Owner ตัดสินใจเปิดตัวแบบไม่มีสินค้า Robux เงื่อนไขนี้จะไม่เป็น Unconditional Release Blocker ต่อการเปิด Public Alpha

## 6. Project Scope & Limitations

1. **Documentation-Only Scope:** งานในรอบนี้จำกัดเฉพาะการปรับปรุงเอกสารแผนงาน Release-First Track และ Data Schema เท่านั้น
2. **No Source/Test Mutations:** ไม่มีการแก้ไขไฟล์โค้ดใน `src/` หรือ `tests/`
3. **No Code Cleanup Execution:** การถอดโค้ดจริงจะยังไม่เริ่มต้นขึ้นจนกว่าจะได้รับอนุมัติแผนงานจาก Owner และผ่านขั้นตอน Read-only Dependency Closure Discovery
4. **Pending Owner Decisions:**
   - **Body Check:** การรวมใน Alpha Launch หรือ Defer ไป Phase 2 รอคำวินิจฉัยจาก Owner
   - **Duplicate Character Outcome:** นโยบายการจัดการตัวละครซ้ำรอคำวินิจฉัยจาก Owner โดยระหว่างนี้ใช้โมเดล Per-copy ownership เก็บรักษาทุกสำเนา
   - **Robux Product:** การวางจำหน่ายสินค้า Robux ในรอบ Alpha ขึ้นอยู่กับการตัดสินใจของ Owner (หากไม่จำหน่าย จะไม่บล็อกการเปิดตัว)
