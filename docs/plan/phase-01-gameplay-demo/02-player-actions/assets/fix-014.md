## 1. Executive Summary & Core Changes

### 1.1 Core FakeShot Aimed Lateral Ball Cut (Owner Delta §23 / T-16 / Spec 02)
- **Problem:** Previously, pressing `E` while charging Direct/Curve shot canceled the shot in place ("แบบล็อคบอลหนี") without moving the ball laterally.
- **Implementation:**
  - Added `Constants.FAKE_SHOT_BALL_CUT_OFFSET_STUDS = 1.4` and `Constants.FAKE_SHOT_BALL_CUT_FORWARD_STUDS = 1.8`.
  - Added shared resolver `PlayerActionPoseConfigs.ResolveFakeShotSideFromAim(hrpCFrame, aimDirection)` returning `("Left"|"Right"|"Neutral", sideSign)`. When player aims right of character facing, `sideSign = +1`; when left, `sideSign = -1`. Pure forward aim defaults to `"Neutral"` (`sideSign = +1`).
  - Removed dead/shadowed duplicate `ExecuteFakeShot` definition in `src/server/services/BallService.luau` (previously defined twice at lines ~2035 and ~2083).
  - Authoritative `ExecuteFakeShot(player, intentId, aimDirection)` in `BallService.luau`:
    - Validates grounded attacking charge context, resolves side from `aimDirection`.
    - If player possesses the ball: displaces ball along `hrp.Position + forward * forwardOffset + right * (sideSign * lateralOffset)`, maintaining full physical contest/tackleability.
    - Synchronizes `FakeShotSide` attribute and sets `st.fakeShotRecoveryUntil = now + FAKE_SHOT_RECOVERY_SEC`.
    - Nonpossessor FakeShot: cancels cosmetic charge but **never** gains or displaces ball (`(ballPos - ballPosBefore).Magnitude < 0.01`).

### 1.2 Live Curve Selection During Charge (Owner Delta §22 / T-15)
- **Problem:** §20 latched curve style at initial RMB press, preventing changing shot type while holding RMB.
- **Implementation:**
  - Removed the initial press lock in `InputController.luau` and `BallService.luau`.
  - In `InputController.luau`: `RenderStepped` samples current movement/keys dynamically while holding RMB, updating `currentChargeCurveSide` and blending procedural hold pose without restarting charge or resetting power.
  - On release, `RequestKick` sends latest release-time `curveSideIntent`.
  - Server `HandleActionRequest` / `ExecuteKick` evaluates release payload and current character movement using `ResolveCurveSideFromMovement`.
  - Test transitions: `D -> hold -> A -> release` resolves to **Finesse** (inside of right foot, curl right-to-left); `A -> hold -> D -> release` resolves to **Trivela** (outside of right foot, curl left-to-right).

### 1.3 TC-P02-33 Edge-Fall Consistency & Airborne Stun Isolation
- **Problem:** In `TC-P02-33`, a rejected jump on an edge fall synced `IsAirborne=false` via `syncPlayerAttributes`, which allowed a subsequent Dash check to erroneously succeed. In `Tier1_StateJumpPhysics.luau`, an airborne whiff was improperly triggering ground walk speed reduction.
- **Implementation:**
  - Guarded `syncPlayerAttributes` in `BallService.luau` against overwriting `IsAirborne=true` to `false` when character root is physically airborne or raycast misses ground.
  - In `ExecuteDirectionalJump` and `ExecuteDash`, marked `st.isAirborne = true` and `st.flightState = "Falling"` on edge fall failure.
  - In `ResolvePlayerSpeed` and `ExecuteKick`, isolated `whiffRecoveryAction == "AirWhiff"` so airborne whiffs consume flight budget without applying ground walk speed penalty (`WalkSpeed >= Constants.WALK_SPEED`).
