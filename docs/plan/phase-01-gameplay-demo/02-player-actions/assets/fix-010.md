## 1. Executive Summary & Root Cause Analysis

### 1.1 Defect Description (F-35 / P1)
During airborne flight (following a directional jump), shots fired with S (backtilt) or any mouse-aim azimuth differing from character flight facing were reported to consistently travel along one locked horizontal direction. The shot appeared bicycle-like because camera yaw was ignored by the client before transmitting the shot intent to the server.

### 1.2 Confirmed Static Root Cause
In `src/client/controllers/InputController.luau`, the internal aim-acquisition helper `getAimDirection()` at lines 128–132 contained an airborne aim-reconstruction block:
```luau
-- BEFORE (Defective Code in 5c33d5f):
local function getAimDirection(): Vector3
    local cam = Workspace.CurrentCamera
    ...
    if cam then
        local look = cam.CFrame.LookVector
        if isAirborneLocked and jumpCommitDir.Magnitude > 0.001 then
            local pitchY = math.clamp(look.Y, -0.85, 0.85)
            local horizScale = math.sqrt(math.max(0.01, 1 - pitchY * pitchY))
            local lockedDir = Vector3.new(jumpCommitDir.X * horizScale, pitchY, jumpCommitDir.Z * horizScale)
            return if lockedDir.Magnitude > 0.001 then lockedDir.Unit else jumpCommitDir
        end
        return look
    end
```
Whenever `isAirborneLocked == true`, `getAimDirection()` discarded `look.X` and `look.Z` from `Workspace.CurrentCamera.CFrame.LookVector` and forcibly substituted `jumpCommitDir.X` and `jumpCommitDir.Z`. Consequently:
1. `InputController.RequestKick` invoked `getAimDirection()` and populated `aimDirection` in the `BallActionRequest` payload with an aim vector that was already locked to `jumpCommitDir`.
2. Downstream `BallService.ExecuteKick` and `AirLeanSolver.ComputeAirShotTrajectory` received this pre-locked horizontal direction. The aim-relative lean solver deflected the ball only around `jumpCommitDir`, so the ball always fired along the flight direction regardless of mouse reticle placement.

### 1.3 Correction Applied
1. **Removed Airborne Aim Reconstruction:** Deleted lines 128–133 in `src/client/controllers/InputController.luau`. `getAimDirection()` now returns the true 3D camera look vector (`cam.CFrame.LookVector.Unit`) in both ground and air states, preserving the fallback to `hrp.CFrame.LookVector` when camera is nil.
2. **Exported Public Method:** Added `InputController.GetAimDirection(): Vector3` to allow both production callers and automated test harnesses to inspect the exact vector produced by the client aim acquisition pipeline.
3. **Preserved Character Facing Lock Invariant:** The character's physical root yaw (`HumanoidRootPart.CFrame`) remains strictly locked to `jumpFacingF0` (`jumpCommitDir`) throughout the jump. The character is **never** rotated to face the camera.
4. **Enhanced Test Suite (TC-ALP-11):** Added end-to-end verification in `tests/e2e/Tier1_AirLeanPhysics.luau` testing camera aim yaw at $0^\circ, +60^\circ, -60^\circ, 180^\circ$ during airborne flight with locked character facing and S-lean.
