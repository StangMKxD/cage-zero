## 1. Executive Summary & Confirmed Root Causes

### 1.1 Owner Acceptance & Remaining Issues (§19 & §20)
1. **Preserved Finesse & Trivela Animations (§19.1):** The Owner visually accepted the procedural R6 charge/release poses for right-foot `Finesse` and `Trivela`. No keyframe numbers, limb poses, or pose names were altered or swapped.
2. **Root Cause A — Raw Keys Overriding Actual Character-Relative Movement (§19.2):**
   - `InputController.getCurveSideIntent()` previously evaluated `if keyADown and not keyDDown then return "Left"` before inspecting `hum.MoveDirection`, and `BallService.ExecuteKick` had no server-side fallback to `humanoid.MoveDirection` when `curveSideIntent` was omitted.
   - **Fix:** Added `PlayerActionPoseConfigs.ResolveCurveSideFromMovement(hrpCFrame, moveDirection, keyADown, keyDDown)` as the shared resolver used by both Client and Server. Priority #1 is actual character-relative horizontal movement (`localMove = hrpCFrame:VectorToObjectSpace(flatMove.Unit)`):
     - `localMove.X < -0.12` $\to$ `"Left"` $\to$ **Right-foot Finesse** (inside of right foot).
     - `localMove.X > +0.12` $\to$ `"Right"` $\to$ **Right-foot Trivela** (outside of right foot).
     - `|localMove.X| <= 0.12` (pure forward/backward movement) $\to$ `"Neutral"` $\to$ **Right-foot Finesse** default.
   - Stationary-only fallback (`flatMove.Magnitude <= 0.08`) uses `keyADown` / `keyDDown` and never overrides contradictory actual character movement.
3. **Root Cause B — Reversed Signed Lateral Magnus Curvature in `BallService.ExecuteKick` (§19.5):**
   - In `BallService.ExecuteKick`, `rightVec = Vector3.new(-horizUnit.Z, 0, horizUnit.X).Unit` points to the **right** of the horizontal shot direction (`+X` when shooting North `-Z`).
   - Because `SHOOT_FINESSE_SPIN_Y = +52.0` (`+Y` CCW spin) and `SHOOT_TRIVELA_SPIN_Y = -56.0` (`-Y` CW spin), the previous formula `curveForce = rightVec * (curveRes.spinY * ...)` applied a `+rightVec` (rightward) lateral acceleration for Finesse and a `-rightVec` (leftward) lateral acceleration for Trivela — the exact opposite of right-foot inside/outside curl.
   - **Fix:** Changed `BallService.ExecuteKick` line 888 to `local curveForce = -rightVec * (curveRes.spinY * curveRes.magnusFactor * (0.6 + (charge * 0.4)))` without altering spin constants or the ball physics integrator:
     - **Right-foot Finesse (`Left` / `Neutral`, `spinY = +52.0`):** `dot(curveImpulse, rightVec) < 0` $\to$ ball curls **right-to-left** (`-rightVec`, inward for right foot).
     - **Right-foot Trivela (`Right`, `spinY = -56.0`):** `dot(curveImpulse, rightVec) > 0` $\to$ ball curls **left-to-right** (`+rightVec`, outward for right foot).
4. **Root Cause C — Resampling Curve Selection on RMB Release (§20):**
   - Previously, `InputController.RequestKick` called `getCurveSideIntent()` again on `MouseButton2` release, and `BallService.ExecuteKick` resolved the curve style from the release payload. Pressing `D` + `RMB down` and then switching to `A` before releasing `RMB` flipped the shot from `Trivela` to `Finesse`.
   - **Fix:** Latched `chargeCurveSide`, `chargeCurveStyle`, and `chargeKickFoot` at the **initial accepted `CurveShoot` charge press** (`RequestStartCharge` on Client and `BallService.StartCharge` on Server, replicated via character attributes `ChargeCurveSide`, `ChargeCurveStyle`, `ChargeKickFoot` and `GetPlayerMovementSnapshot()`).
   - During hold and on release, both Client (`RequestKick`) and Server (`HandleActionRequest` / `ExecuteKick`) strictly use the frozen charge snapshot and ignore any changed movement or opposite A/D key press (`D -> RMB down -> A -> RMB up` stays `Trivela`; `A -> RMB down -> D -> RMB up` stays `Finesse`).
   - Camera 3D aim (`aimDir`) and charge ratio (`charge`) remain freely adjustable until release.
   - The frozen snapshot is cleared on release, `CancelCharge`, `ExecuteSlide`, `ResetBall`, context switch (`Attacking <-> Defending`), rejection, window focus loss, character death, and respawn (`characterGeneration` increment).
