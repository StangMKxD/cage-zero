## 2. การสืบสวนและพิสูจน์สาเหตุรากเหง้า (Root Cause Proof: F-15 & F-28)

### 2.1 พฤติกรรมที่สังเกตพบใน Review-005
ใน `review-005.md` และ `codex-moving-jump-partial-20261022.json` พบหลักฐานเชิงประจักษ์:
- การทดสอบ `Walk + Space`: $W$ กด $200$ms $\to$ $Space$ กด $100$ms $\to$ ปล่อย $Space$ $\to$ รอ $900$ms
- ที่เวลา $t = 0.05052$s หลังเริ่มกระโดด: ความเร็วดิ่ง $vy$ เปลี่ยนจาก $+70.5975$ studs/s เป็น $-4.0875$ studs/s ภายในช่วงเวลา $dt = 0.01692$s
- ส่งผลให้ตัวละครขึ้นถึงจุดสูงสุดเพียง $Y = 5.539$ studs (ยกตัวขึ้นเพียง $2.449$ studs จากระดับพื้น $Y = 3.090$) และตกกระทบพื้นเร็วเกินไปที่ $t = 0.31623$s
- ขณะเกิดความผิดปกติ Client Flight กลายเป็น `idle` ขณะที่ Server Replicated `IsAirborne` ยังเป็น `true`

### 2.2 การพิสูจน์ Writer และกลไกความผิดพลาด (Proven Mechanism)
จากการตรวจสอบ Trace ของทุกโมดูลที่เขียนค่า `AssemblyLinearVelocity` และการเปรียบเทียบกับ `prototype3`:
1. **Network Ownership Disconnect:**
   - ใน Roblox ตัวละครของผู้เล่นมี Network Ownership อยู่ที่เครื่อง Client ดังนั้น Client จึงเป็นผู้ขับเคลื่อนฟิสิกส์ของ `Humanoid` ตามคำสั่งกระโดดของเอนจิน Roblox
   - เมื่อกดกระโดดในขณะเดินหรือวิ่ง (`jumpDirection.Magnitude > 0.08`):
     - ฝั่ง Client (`InputController.luau`) ได้ส่งรีโมต `commitJumpDirection` ไปยัง Server
     - เมื่อ Server (`BallService.luau`) ได้รับรีโมต ในฟังก์ชัน `ExecuteDirectionalJump` (เดิมบรรทัด 1044) และในลูป `StepPhysics` (เดิมบรรทัด 1251):
       ```luau
       rootPart.AssemblyLinearVelocity = Vector3.new(st.jumpLockedVelocity.X, rootPart.AssemblyLinearVelocity.Y, st.jumpLockedVelocity.Z)
       ```
2. **Replication Latency & Stale Vertical Velocity Packet:**
   - เนื่องจากมีความล่าช้าในการสื่อสารเครือข่าย (Network Latency $\approx 30\dots 50$ms) ค่า `rootPart.AssemblyLinearVelocity.Y` ที่ Server อ่านได้ในขณะที่รีโมตมาถึง ยังคงเป็นค่าความเร็วดิ่งของตัวละครที่ยังอยู่บนพื้นหรือเพิ่งเริ่มขยับ (ซึ่งมีค่าติดลบเล็กน้อยประมาณ $-3.27 \dots -4.08$ studs/s จากแรงโน้มถ่วงที่กดตัวละครลงกับพื้น)
   - การที่ Server สั่งเขียนค่า `rootPart.AssemblyLinearVelocity` จะทำให้ Server ส่งแพ็กเก็ตฟิสิกส์ที่มีอำนาจเหนือกว่า (Authoritative Physics Replication Packet) ย้อนกลับมายัง Client
   - เมื่อ Client ได้รับแพ็กเก็ตดังกล่าวที่เวลา $t \approx 0.035 \dots 0.050$s เอนจินฟิสิกส์ของ Client จึงถูกบังคับเขียนทับความเร็วดิ่ง $+70.60$ studs/s ด้วยค่า $-4.08$ studs/s ในทันที! ทำให้แรงส่งกระโดดทั้งหมดดับลงกลางคัน
3. **เหตุผลที่ Stationary Jump ไม่เกิดปัญหานี้:**
   - เมื่อผู้เล่นกระโดดขณะยืนนิ่ง (`jumpDirection.Magnitude <= 0.08`) ค่า `st.jumpLockedVelocity` บน Server จะมีค่าเป็น `nil` ทำให้ Server ไม่เข้าไปแตะต้องหรือเขียนทับ `rootPart.AssemblyLinearVelocity` เลยแม้แต่น้อย ปล่อยให้ฟิสิกส์ของ Client ทำงานได้อย่างอิสระ จึงเป็นคำตอบว่าทำไม Stationary Jump ถึงกระโดดได้สูงปกติ
