## 1. สรุปผลการแก้ไข Finding IDs (F-10 ถึง F-19)

### F-10 (P1 / CLOSED): Opponent Possession Contest Continuous Contact & No Global Immunity
- **ปัญหาเดิม:** บอลในสถานะ `Possessed` ตรวจเพียงตำแหน่งผู้ครองบอล ไม่มีการตรวจการสัมผัส/แย่งบอลจากผู้เล่นอื่น และมี guard ปิดการตรวจการสัมผัส 0.30 วินาทีหลังเตะ ทำให้บอลและผู้เล่นที่กำลังเลี้ยงบอล/แดช วิ่งทะลุคู่แข่งได้โดยไม่ถูกตัดบอล
- **การแก้ไข:**
  1. ใน `BallService.luau` ปลด Global 0.3s Kick Immunity ให้เหลือเฉพาะ `isKickerCooldown = (userId == ballState.lastKickerUserId and (now - ballState.lastKickTime) < 0.22)` สำหรับผู้เตะคนเดิมเท่านั้น
  2. ในช่วง `Possessed` เพิ่มการตรวจระยะสัมผัสของผู้เล่นฝ่ายตรงข้าม (`dist <= Constants.BALL_TOUCH_RADIUS`) หากผู้เล่นฝ่ายรับเข้ามาในระยะ จะเกิดการแย่งบอล (Tackle/Contest) และโอนสิทธิ์การครองบอลไปยังผู้เล่นฝ่ายรับทันที
- **หลักฐานการตรวจรับ:** ผ่าน `TC-P02-27_OpponentPossessionContestContinuousContact` และ `TC-P02-28_CloseOpponentContactAfterKickNoGlobalImmunity`

### F-11 (P1 / CLOSED): High Aerial Jump Block Swept Collision (Y > 3.8)
- **ปัญหาเดิม:** โค้ดเดิมตรวจการชนเฉพาะจุดปลาย step และจำกัด world Y ของบอลต้อง `<= 3.8` ทำให้ลูกบอลที่ลอยสูงกว่า 3.8 studs ทะลุตัวผู้เล่นที่กระโดดบล็อกกลางอากาศ
- **การแก้ไข:**
  1. ใน `BallService.luau` ใช้ Swept Segment `[prevPos, nextPos]` คำนวณจุดที่ใกล้ที่สุดบนเส้นทางของบอลเทียบกับผู้เล่น (`closestPt`)
  2. คำนวณความสูงสัมพัทธ์ตามร่างจริงของผู้เล่น: `playerBaseY = rootPart.Position.Y - 2.0` ถึง `playerHeadY = rootPart.Position.Y + 2.5` ทำให้ผู้เล่นที่กระโดดอยู่ที่ Y = 6.0 สามารถบล็อกบอลที่ Y = 6.0 ได้อย่างแม่นยำ
  3. บอลความเร็วสูง (> 65.0 studs/s) สะท้อนกลับ (Deflect) ในทิศทางตรงกันข้ามกับเวกเตอร์ขาเข้า (`deflectDir = -incomingDir`) พร้อมแรงกระดอนขึ้น `+10.0` studs/s
- **หลักฐานการตรวจรับ:** ผ่าน `TC-P02-29_HighAerialJumpBlockSweptCollision`

### F-12 (P1 / CLOSED): First-Time Intents Preserved Without Prior Possession
- **ปัญหาเดิม:** เมื่อผู้เล่นกดคำสั่งเล่นจังหวะแรก (First-Time Play) โค้ดเดิมบังคับเปลี่ยนทุกคำสั่งเป็น Header หรือ Volley เสมอ โดยไม่สนใจประเภทคำสั่ง (GroundPass, LobPass, CurveShoot ถูกทิ้งทั้งหมด)
- **การแก้ไข:**
  1. ใน `BallService.ExecuteKick` รักษา intent ของผู้เล่นครบทุกประเภทเมื่อบอลอยู่ในระยะสัมผัส (`distToBall <= Constants.BALL_TOUCH_RADIUS`):
     - `GroundPass`: ความเร็ว 85 studs/s พุ่งเรียดพื้น Y velocity = 0.5
     - `LobPass`: ความเร็ว 45 studs/s พร้อมแรงยกขึ้น Y velocity = 28 studs/s
     - `CurveShoot`: คำนวณความเร็วและแรงดัดโค้ง (Curve Force) ไปตาม right vector ของมุมเล็ง
     - `DirectShoot`: ตรวจความสูงสัมพัทธ์ `relY >= 0.5` หรือ airborne ให้เป็น `Header` (88 studs/s) หรือ `Volley` (118 studs/s)
- **หลักฐานการตรวจรับ:** ผ่าน `TC-P02-30_FirstTimeIntentsPreservedWithoutPriorPossession`

### F-13 (P1 / CLOSED): Numeric Validation, Safe Aim Normalization & Alive Check
- **ปัญหาเดิม:** Payload `charge` ตรวจเพียง `type == number` ไม่กัน NaN/Inf; aim แนวตั้ง `(0, 1, 0)` ทำให้การ normalize เกิดเวกเตอร์ศูนย์หรือ NaN; ไม่มีการตรวจ alive/Humanoid และ rate limit
- **การแก้ไข:**

  2. ตรวจสอบ `Network.IsFiniteVector3(aimVector)` และทำการ normalize เฉพาะระนาบแนวนอน (`horizAim = Vector3.new(aim.X, 0, aim.Z)`); หาก aim เป็นแนวตั้งบริสุทธิ์ จะ fallback ไปใช้ `rootPart.CFrame.LookVector` ทันที ป้องกัน NaN 100%
  3. ตรวจสอบ `humanoid.Health > 0` ก่อนประมวลผลคำสั่งทุกประเภท (Kick, Jump, Dash, Sprint)
  4. ป้องกัน final velocity และ curve impulse ด้วย `Network.IsFiniteVector3` ก่อนบันทึกลง `ballState`
- **หลักฐานการตรวจรับ:** ผ่าน `TC-P02-25_ZeroDistanceDeflectionSafeGuard` และ `TC-P02-31_PayloadValidationAndDeadCharacterRejection`

## 2. การแก้ไขฟิสิกส์และการเล่นตามที่ระบุในคำสั่ง (Physics & Gameplay Fixes)

1. **ลูกบอลลอยเหนือพื้น (Ball Floating Above Floor):**
   - **สาเหตุจริง:** ใน `BallService.luau` มีการบวกแรงโน้มถ่วงแนวตั้ง (`GRAVITY_ACCELERATION_Y * dt`) ใส่ลงใน `velWithGravity` ทุกเฟรม แม้ลูกบอลจะวางอยู่บนพื้นหญ้าแล้วก็ตาม เมื่อส่งเข้าสู่ `CagePhysicsService.StepBallCageCollision` ฟังก์ชันดังกล่าวตรวจพบว่า `p.Y < radius` และ `v.Y < 0` จึงคำนวณแรงสะท้อนยืดหยุ่น (`ComputeReboundVelocity` ด้วย `FLOOR_RESTITUTION = 0.75`) ส่งผลให้บอลมีแรงกระดอนขึ้น (`nextVel.Y = +4.0` studs/s) ทุกเฟรม ความเร็วจึงเกิน `BALL_REST_THRESHOLD_SPEED` (0.6) ตลอดเวลา ทำให้ลูกบอลกระดอนแบบไมโครรีบาวด์ลอยค้างอยู่เหนือพื้นสนามประมาณ 0.26 studs (center Y ~ 1.51 studs) ไม่ยอมแนบติดพื้นหญ้า
   - **การแก้ไขตามต้นแบบ `prototype3`:**
     1. ตรวจจับสถานะบนพื้นหญ้า `onGround = not isOnRamp and (ballState.position.Y <= r + 0.08) and (math.abs(ballState.velocity.Y) < 3.0)`
     2. เมื่อลูกบอลอยู่บนพื้นหญ้า: ระงับแรงโน้มถ่วงแนวตั้ง (`currentVel = Vector3.new(currentVel.X, 0, currentVel.Z)`) และล็อกระดับแกนดิ่งที่ `Constants.BALL_RADIUS` (1.25 studs) ป้องกันไม่ให้ตัวตรวจจับการชนของสนามคำนวณแรงกระดอนขึ้น
     3. เมื่อบอลตกลงมาจากอากาศ: หากความเร็วแนวดิ่ง `nextVel.Y < -3.5` จะยอมให้เกิดการกระดอนแบบฟิสิกส์ แต่เมื่อความเร็วแนวดิ่งลดลงต่ำกว่าเกณฑ์ จะเข้าสู่การสัมผัสพื้นหญ้า (`nextPos.Y = r`, `nextVel.Y = 0`) และชะลอความเร็วด้วยแรงเสียดทานการกลิ้ง (`GROUND_ROLLING_FRICTION`) จนกระทั่งหยุดนิ่งสนิทที่ $Y = 1.25$ studs พอดี โดยมีระยะห่างจากพื้นผิวสนามหญ้าเป็น 0.000 studs (ไม่มีการลอยตัวอีกต่อไป)

   - **การแก้ไขตามต้นแบบ `prototype3`:**

     2. คำนวณทิศทางการแดช: หากตัวละครกำลังเคลื่อนที่ (`hum.MoveDirection.Magnitude > 0.05`) ให้พุ่งไปตามทิศทางการเดิน; หากยืนนิ่ง ให้พุ่งไปตามเวกเตอร์แนวราบของมุมกล้อง (`Vector3.new(camLook.X, 0, camLook.Z).Unit`)

     2. ใน `RenderStepped` มีการเช็ค `local isAir = (hum.FloorMaterial == Enum.Material.Air) or (hrp.Position.Y > 3.4)` ซึ่งในเฟรมแรกของการกดกระโดด `FloorMaterial` ยังคงเป็น Concrete และความสูงยังไม่เกิน 3.4 studs ทำให้ `isAirborneLocked` ถูกปลดล็อกทันทีในเฟรมถัดไป แล้วกลับมาล็อกใหม่เมื่อลอยขึ้น ก่อให้เกิดอาการกระตุกและติดขัด
   - **การแก้ไขตามต้นแบบ `prototype3`:**

   - **ระบบรีเซ็ตบอลเร็ว (Reset Ball):** กด `X` รีเซ็ตลูกบอลกลับสู่จุดกึ่งกลางสนาม $Y = 1.25$ studs ทันที
