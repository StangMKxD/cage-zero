## 3. รายละเอียดการแก้ปัญหา F-05: Generic Recursive Comparator

### 3.1 การเอาชนะขีดจำกัดความยาวโค้ดของ Roblox Studio (Engine Constraint)
Roblox Studio Engine มีข้อจำกัดความปลอดภัยของ DataModel คือ ไม่อนุญาตให้ `Script.Source` มีความยาวเกิน **200,000 ตัวอักษร** (`Unable to assign property Source. Provided string length >= 200000`) 
หากนำ post-state snapshot ฉบับดิบ (2.55 MB) หรือ cleaned JSON (318 KB) ฝังลงในสคริปต์ จะล้มเหลวทันทีที่สร้างหรือโหลดสคริปต์

**แนวทางแก้ไข:**
สร้าง **Dictionary-Packed Tuple Representation** ใน [restore.ps1](file:///C:/Users/Stang/cage-zero/.sandbox/rollback/run-phase01-cage-physics-01/restore.ps1):
- สกัดชื่อ, ClassName และ Material ออกมาเป็นตาราง `dict` (1,215 รายการ)
- บันทึกแต่ละ node เป็น tuple กะทัดรัด: `[nameIdx, classIdx, attributes, size_or_spotlight, cframe, flags, transparency, materialIdx, children]`
  - `flags`: เก็บ `(CanCollide ? 1 : 0) | (Anchored ? 2 : 0)` เป็น bitfield
  - `cframe`: หาก rotation matrix เป็น Identity Matrix (`[1,0,0, 0,1,0, 0,0,1]`) จะย่อเหลือเฉพาะเวกเตอร์ตำแหน่ง `[x, y, z]`
- ผลลัพธ์: บีบอัดข้อมูล 1,205 nodes ของ `HexCageArena` และ 2 nodes ของ `Baseplate` เหลือ JSON เพียง **99,906 bytes** รวมกับโค้ด Luau ตัวสคริปต์มีขนาด **189,740 bytes** (ผ่านเกณฑ์ < 200,000 ตัวอักษรอย่างปลอดภัย)

### 3.2 กลไกการทำงานของ Recursive Comparator (`compareTupleTree`)
ฟังก์ชัน `compareTupleTree(liveNode, tuple, path)` ทำงานดังนี้:
1. **Node Identity & Class:** เทียบชื่อและ ClassName หาก live node หายไปหรือ ClassName ผิด จะรายงานทันที
2. **Attributes:** วนลูปตรวจทุก Attribute ตาม snapshot รองรับ tolerance สำหรับตัวเลข (`abs <= 0.01`) และ Vector3 (`Magnitude <= 0.05 studs`)
3. **BasePart Properties:**
   - `Size`: ตรวจ 3 มิติ (tolerance 0.05 studs)
   - `Position`: ตรวจ 3 มิติ (tolerance 0.05 studs)
   - `Rotation Matrix`: ตรวจ 9 ค่าของ CFrame matrix (tolerance 0.01) โดย default เป็น identity หาก tuple มีเฉพาะ 3 ค่า
   - `CanCollide` และ `Anchored`: ตรวจ exact boolean
   - `Transparency`: ตรวจ tolerance 0.02
   - `Material`: ตรวจผ่าน string lookup ใน `dict`
4. **SpotLight Properties:** ตรวจ Brightness, Range, Angle, Enabled สำหรับ SpotLights ใน `UrbanBackdrop`
5. **Two-Way Child Reconciliation:**
   - แม็ป direct children ทั้งหมดของ live node ลงใน lookup table (`liveMap[name]`)
   - เดินตรวจทุก expected child: หากไม่มีใน liveMap รายงาน `Missing child node`; หากมี เรียก `compareTupleTree` ซ้ำลงไปในเชิงลึก (recursive)
   - ตรวจสอบ child ส่วนเกิน: หาก live child ไม่อยู่ใน snapshot รายงาน `Unexpected extra node`
